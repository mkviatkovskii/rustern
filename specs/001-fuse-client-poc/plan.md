# Implementation Plan: Read-Only FUSE Client Proof of Concept

**Branch**: `001-fuse-client-poc` (no git branch) | **Date**: 2026-11-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-fuse-client-poc/spec.md`

## Summary

Mount a TernFS cluster read-only and serve lookup, getattr, readdir(plus), readlink, open
and read with CRC-verified bytes, refusing every mutation with EROFS. Hand-written code is
limited to TernFS logic: wire codecs are generated from upstream `go/msgs` by a generator
adapted from `bincodegen`; FUSE, async I/O, retries, span-map caching, CLI,
logging and metrics come from established crates (`fuser`, `tokio`, `dashmap`, `backon`,
`moka`, `clap`, `tracing`, `metrics`). FUSE callbacks reach an async `AsyncFilesystem`
trait through a small bridge, modelled on fuser's experimental async API, which covers
too few operations to use directly (R1). The workspace foundation (crate split, lints, dependency
policy, one gate script) is built as part of this feature. Details: [research.md](research.md).

## Technical Context

**Language/Version**: Rust stable 1.100.0, edition 2024, pinned via `rust-toolchain.toml`; Go 1.27 for the code generator and golden vectors (development time only)

**Primary Dependencies**: `fuser` 0.18, `tokio` 1, `bytes` 1, `futures-util` 0.3, `dashmap` 6, `deadpool` 0.13, `memmap2` 0.9, `backon` 1, `fastrand` 2, `moka` 0.12, `rustix` 1, `crc-fast` 1.10, `thiserror` 2, `clap` 4, `tracing` 0.1, `tracing-subscriber` 0.3, `metrics` 0.24, `metrics-exporter-prometheus` 0.18 (see Dependency Justification)

**Storage**: TernFS cluster at upstream pin `5550891` (protocol reference: `go/msgs`, `go/client`, `go/core`); local cluster via `ternrun -leader-only`

**Testing**: `cargo-nextest`, `proptest`, `cargo-fuzz` (nightly, fuzzing only) with a stable corpus-replay test, golden vectors from `tools/goldens`, `criterion`, `dhat` (allocation counts, one test), no `loom` model tests in the PoC (CT-6), cluster integration/differential/fault suites driven by `scripts/gate.sh`, `fio` for macro benchmarks

**Target Platform**: Linux, x86_64 primary

**Project Type**: Library-first Cargo workspace with a FUSE daemon binary

**Crates Touched**: all new: `rustern-msgs`, `rustern-core`, `rustern-client`, `rustern-fuse`, `rustern`. `rustern-fuse` holds no protocol logic (only translation between FUSE calls and `rustern-client`); `rustern-client`, `rustern-core` and `rustern-msgs` have no FUSE dependency (checked by the gate)

**Performance Goals**: from the spec, recorded not gated: `seq-read` ≥ 50% of ternfuse at 1/4/16 readers and ≥ 2× from 1→4 readers; `rand-read` ≥ 50%; `meta-latency` and `readdir-latency` p99 ≤ 2× ternfuse; CPU/GiB ≤ 2×; read buffers within `--memory-limit`, peak RSS recorded

**Constraints**: no panics on request paths (lint-enforced); every allocation from network input bounded by the received length; in-flight block data ≤ `--memory-limit` (1 GiB) in total and ≤ `--file-memory-limit` (32 MiB) per file, shared by its open handles; caller-facing deadlines ≤ 60 s; no mutating request ever sent; file data copied once, into the kernel (R12)

**Scale/Scope**: corpus ≥ 1,000 files / 100 directories, files up to 1 GiB, directories up to 10,000 entries, 16 concurrent readers, 256 shards

### Dependency Justification

| Crate | Purpose | Why not in-tree or an existing dependency | Features enabled | `cargo-deny` clean |
|-------|---------|-------------------------------------------|------------------|--------------------|
| `fuser` | FUSE protocol and mount | Kernel protocol implementation is large and well-trodden | default (none) | yes |
| `tokio` | Async runtime, sockets, timers, signals | Baseline | `rt-multi-thread`, `net`, `time`, `sync`, `signal`, `macros`, `io-util` | yes |
| `bytes` | Zero-copy buffers for codecs | Baseline | default | yes |
| `futures-util` | `try_join_all` over fetches borrowing disjoint buffer slices (R12) | tokio has no join-all; already a `moka` dependency | default features off, `std` | yes |
| `dashmap` | Pending UDP requests by id; idle block connections per address | Concurrent map without a global lock; baseline lists it | default | yes |
| `deadpool` | Read-buffer pool: lazy creation up to `max_size`, waits when exhausted, LIFO reuse (R12, FR-012) | A bounded async pool is generic; 171M downloads; replaces a semaphore plus a hand-written stack | default features off, `managed` | yes |
| `memmap2` | Read buffers as slices of one anonymous mapping advised `MADV_HUGEPAGE` | `std` cannot map memory or call `madvise`; safe API for both; 428M downloads | default | yes |
| `backon` | Per-attempt timeout schedule (initial, growth, max) | Retry schedules are easy to get subtly wrong; maintained, 114M downloads; used as an iterator only (R4) | default features off, `std` | yes |
| `fastrand` | ±5% jitter on per-attempt timeouts | Already a `backon` dependency; no new code compiled | default | yes |
| `moka` | Bounded span-map cache with single-flight loading | One span-map load for concurrent callers with no hand-written code; baseline lists it | `future` | yes |
| `crc-fast` | Hardware CRC32C (`crc32_iscsi`), combine | About 2x faster than `crc32c` at 128 KiB and up, 35% on 4 KiB pages (T109); 81M downloads; has combine. Pulls `digest`, `crypto-common`, `generic-array`, `typenum`, `spin` | default features off, `std` | yes |
| `rustix` | Send SIGUSR1 to the parent for `-signal-parent`, effective uid/gid; `fs` for open-flag decoding (`OFlags`) | `std` has no `kill`, `geteuid` or `O_*` constants; baseline Syscalls entry | `fs`, `process` | yes |
| `thiserror` | Typed errors in every crate, including `main` (exit code chosen by matching) | Baseline | default | yes |
| `clap` | Command-line parsing | Baseline | `derive` | yes |
| `bytesize` | Parse `--memory-limit` and `--file-memory-limit` (`256MiB`, `1GiB`) | Unit parsing and printing; 30M+ downloads, no dependencies | default | yes |
| `tracing`, `tracing-subscriber` | Structured logging | Baseline | `fmt`, `env-filter` | yes |
| `metrics`, `metrics-exporter-prometheus` | Counters, histograms, text rendering for the SIGUSR1 dump | Baseline | exporter: default features off (no HTTP listener) | yes |
| dev: `proptest`, `criterion` 0.8, `dhat`, `crc32c` | Testing; `dhat` counts allocations per read in one test (CT-4); `crc32c` (the first choice) only as the CRC benchmark baseline (T109) | Baseline verification list (all dev-only) | default | yes |

## Complexity Tracking

Exceptions are time-boxed and reviewed at the next release (Governance).

| Violation | Why Needed | Simpler Alternative Rejected Because | Expires |
|-----------|------------|-------------------------------------|---------|
| CT-2: Principle III, no parity reconstruction (DEV-004) | PoC scope; reconstruction needs Reed-Solomon bit-identical to upstream | In-house RS port plus golden vectors is the largest single piece of hand-written code | Feature adding degraded reads (before v1) |
| CT-3: Principle III, interrupted requests not cancelled (DEV-005) | `fuser` declines FUSE_INTERRUPT | Patching `fuser` or switching to `fuse3` is 1–2 days and adds a fork | Before v1 (deferred follow-up task) |
| CT-4: Principle V, targets recorded not gated; no UDP syscall batching; default allocator; remaining per-request allocations (one task per FUSE request, one `oneshot` per metadata request, decoded response structs), counted with `dhat` (R12) | PoC proves function first; baseline numbers do not exist yet | Gating on unmeasured targets would block the PoC on tuning; removing the last allocations needs custom executors or arenas | Next feature touching the read path |
| CT-5: Principle VII, upstream `terntests` and a POSIX conformance suite not run | Both exercise writes, which the PoC refuses; read-only behaviour is covered by integration and differential tests | Running them would only measure EROFS | First feature with a write path |

Model tests: before v1, or earlier if the demultiplexer gains custom synchronisation beyond `DashMap` and `oneshot` |
